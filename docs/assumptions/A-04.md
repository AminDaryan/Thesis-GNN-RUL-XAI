# A-04 — The smoothing parameter is 0.5

**Where:** `config.PreprocessingConfig.smoothing_alpha`, `data/smoothing/`

**The gap.** Section 3.2.3 of the paper defines the filter as
`S_t = alpha * X_t + (1 − alpha) * S_(t−1)` and then writes: *"S(t-1) indicates
the previous smoothed value, which is equal to 0.5 in this study; alpha
constitutes the smoothing parameter"*. As written, the number 0.5 is attached
to the previous smoothed value rather than to `alpha`.

**What we chose.** Read the sentence as `alpha = 0.5`.

**Why.** In a recursive formula, `S_(t−1)` is a different quantity at every time
step; it cannot be a single fixed number "in this study". The only reading that
makes the sentence meaningful is that 0.5 belongs to the smoothing parameter,
which is the quantity a paper would normally report.

**How much it matters.** `alpha = 0.5` is light smoothing: half the weight
stays on the current reading. The setting can be disabled entirely by setting
it to `null` in the configuration. That measures whether smoothing is worth
having at all, not whether 0.5 is the right value, which has not been measured.

**Measured, 2026-10-19: switching it off costs 1.706 cycles under the default
configuration.** Five seeds each, 42 to 46, split varying with the seed, at
commit `a05da94`. One run is `python scripts/train.py --seeds 5`, the default
settings: the last-cycle stage (A-07), the physics graph with row rescaling,
z-score input scaling, a fifth of the training engines held back and the best
checkpoint restored. The other is the same with `--config` pointing at a copy
of `config/fd001.yaml` whose only change is `smoothing_alpha: null`; the two
runs' stored `preprocessing_config.yaml` files differ in that line and in the
wording of their `notes`, and their `model_config.yaml` files are identical.

The size depends on the configuration, as rule 3 of `CLAUDE.md` warns. F-10
measured +1.219 (p = 0.007) at `09628fa`, with per-condition min-max input
scaling, symmetric graph rescaling and a learning rate that shrank after every
pass, the schedule A-17 chose until 2026-09-01. F-19 found no difference it could
distinguish from zero around the recurrent-stage reference, one LSTM per
sensor at the size A-26 chose, with the best held-back pass restored, at
`fd65a3b-dirty`: −0.070 on test (p = 0.804) and −0.044 held back (p = 0.749),
as `docs/audits/AUDIT_2026-09-08_response.md` tabulates. So what smoothing is
worth under the paper's own procedure, 200 passes with nothing held back, has
not been measured. Why the last-cycle stage should be the more sensitive is an argument,
not a measurement: it passes one number per sensor, so smoothing is the only
way the earlier cycles of a window reach the network, whereas a recurrent stage
reads all of them.

# A-42 — "ESTGNN w/o GCN" removes the three graph layers and puts nothing in their place

**Where:** `models/estgnn.py` (`ESTGNN(..., spatial="none")`, `has_graph_layers`);
`models/config.py` (`ModelConfig.spatial`); `scripts/train.py --spatial none`,
marked `_nogcn` in the run folder's name and `"spatial": "none"` under
`summary.json`'s `model`; the refusals in `explain/walks.py`,
`explain/connections.py`, `explain/flipping.py` and `scripts/explain.py
--method walks`; `models/README.md`, under "A network without graph layers"

**The gap.** Section 4.3 (page 11) says the variants of Table 11 come from
"systematically removing key architectural elements", that "Three variant
configurations are evaluated against the complete ESTGNN framework under
identical experimental conditions", and names the first "ESTGNN without GCN
component (ESTGNN w/o GCN)". Table 11 (page 12) prints its root mean squared
error and nothing else: 16.42, 28.15, 17.67 and 27.52 on FD001 to FD004. The
text below the table says its removal "results in the most significant
performance degradation" and that this "demonstrates the critical role of graph
convolution in capturing sensor interdependencies and spatial relationships".
Nowhere does the paper say what the network looked like once the graph layers
were gone: whether anything stood in for them, how wide the first dense layer
then was, or how many numbers the variant learned. Checked against the PDF's
text layer on 2026-11-13.

**What we chose.** Literal removal. The temporal stage's output, shaped
`(B, 14, F)` — `B` windows, 14 sensors, `F` numbers per sensor, 1 for both the
default stage and the recurrent stage at the size assumption A-26 chose — is
flattened to `(B, 14 × F)` and handed to FC-1 (128 wide, ReLU), then FC-2 (one
output, sigmoid) times the label ceiling, exactly as the full network's flatten
hands its `(B, 448)` on. Nothing else changes: the same temporal stage, the same
dense layers, the same training, the same data. The sensor graph is still kept
inside the network, so a stored network's saved weights load back unchanged,
but nothing in the prediction reads it.

**Why.**

- **It is the most literal reading of "removing".** "w/o LSTM" is read the
  same way: the LSTM stage is left out (assumption A-11), and the last reading
  goes in its place only because the graph layers need one number per sensor
  (assumption A-07). Here nothing downstream needs anything the temporal stage
  does not already give, so nothing has to go in. ("w/o Physics prior" could
  not be read this way, since graph layers cannot run without a graph; its
  stand-in is assumption A-19.)
- **Anything put in the graph layers' place would be a network the paper does
  not describe.** A replacement block — a dense layer per sensor, a block of
  the removed layers' size, a different graph — needs widths, depths and
  activations the paper never prints, so its number would be about a block of
  this project's invention, not about the row.
- **It is the only reading under which 16.42 is the comparison.** Under any
  replacement the result answers a different question from the one Table 11's
  row was printed for, so setting it beside 16.42 would be setting two
  different experiments side by side.

**How much it matters — an argument, not yet a measurement.** Removing the
graph layers removes more than the passing of numbers between sensors: it
removes most of what the network learns. Counted with `count_parameters()` on
the paper's graph for 30-cycle windows:

| Temporal stage | With the graph layers | Without (`--spatial none`) |
|---|---|---|
| `last_cycle`, the default | 61,729 | 2,049 |
| `lstm`, assumption A-26's size | 124,482 | 64,802 |

Without the graph layers FC-1 shrinks from 448 × 128 + 128 = 57,472 numbers to
14 × 128 + 128 = 1,920, and the three graph layers' 1 × 32 + 32 × 64 + 64 × 32
= 4,128 go; FC-2 keeps its 129. With the recurrent stage the stage's own 62,753
stay, so 1,920 + 129 + 62,753 = 64,802. A difference between a network and its
version without graph layers is therefore a difference in connections between
sensors **and** in size at once, and the comparison cannot say which of the two
produced it. That confound is the paper's too, if its variant was built this
way; the paper does not say.

The clean test of the connections alone keeps every learned number and takes
only the passing between sensors away: the same three graph layers on a graph
in which every sensor is joined to itself and to nothing else. Then each graph
layer multiplies each sensor's numbers by the same table of multipliers, sensor
by sensor, and no sensor sees another. The audit of 2026-09-08 measured such a
graph once, over three seeds, at 20.992 ± 1.163 RMSE
(`docs/audits/AUDIT_2026-09-08_scientific_validity.md`, item D-2), under the
architecture of that date and outside any stored run of this repository, so it
is not a result of this project. It is not built here.

With the default stage the network without graph layers is close in kind to
an ordinary model already measured (finding F-22): a network with one hidden
layer of 64 given the default network's fourteen latest readings. It is not
the same network — 128 wide, a sigmoid output times 125, trained by this
project's loop — so F-22's figure is not a figure for it.

**Which published row a run may be set beside.** With `--temporal lstm` and
`--spatial none`, the "ESTGNN w/o GCN" row of Table 11 (16.42 on FD001), under
the same two warnings as the full network: the recurrent stage's size is this
project's choice (assumption A-26), and what that stage is worth depends on
whether the best held-back pass is restored, which the paper never describes
(finding F-16). With the default stage and `--spatial none`, two parts are gone
— the recurrent stage and the graph layers — and no row of the paper removes
both, so none applies.

**Not yet measured.** No five-seed run of either network exists. Completed by:

```bash
python scripts/train.py --config config/fd001.yaml --spatial none --seeds 5
```

each beside the same configuration with its graph layers trained at the same
commit, paired by seed (working rule 3).

**Reproduce the counts with** (no training, a few seconds):

```python
import logging

from thesis_gnn_rul_xai.graph.adjacency import build_physics_adjacency, normalize_adjacency
from thesis_gnn_rul_xai.models import ModelConfig, build_model

logging.disable(logging.INFO)
graph = normalize_adjacency(build_physics_adjacency()[0], method="row")
for temporal in ("last_cycle", "lstm"):
    for spatial in ("gcn", "none"):
        model = build_model(graph, ModelConfig(temporal=temporal, spatial=spatial),
                            window_size=30, rul_max=125)
        print(temporal, spatial, model.count_parameters())
# last_cycle gcn 61729 / last_cycle none 2049 / lstm gcn 124482 / lstm none 64802
```

`tests/test_models.py` checks the four counts and the arithmetic above.
